**Requirements:**

1. **Landing Page:**
    - App title: “PolicyPal”
    - Short tagline: “Understand policies at a glance”
    - File upload input (PDF) and URL input field
    - Submit button: “Summarize Policy”
    - Responsive design for desktop and mobile
2. **Results Page:**
    - Card-based layout for each policy section:
        - Section title (Data Collection, User Rights, Opt-Out Options, Arbitration Clause)
        - Summary text from backend
        - Risk icon (Green check, Yellow warning, Red flag)
    - Optional “Details” expandable section for longer text
    - Optional comparison view (highlight differences if two policies compared)
3. **Integration Points:**
    - Call backend API endpoints: `/summarize_policy` and `/compare_policies`
    - Send uploaded file or URL to backend and receive JSON structured output
    - Render JSON output dynamically into cards with correct colors/icons
4. **Styling:**
    - Use **modern, minimal design** with good spacing and typography
    - Color-coded risk flags: green/yellow/red
    - Clean header/footer with app branding
    - Mobile-first responsive design
5. **Deliverables:**
    - Fully functional Bolt frontend code ready to deploy
    - React-based with components clearly structured
    - Include placeholders for API calls (no hardcoded data)
    - Clear naming conventions for components, props, and state

Make the code **production-ready, modular, and clean**, ready for integration with a backend.


Backend

**Requirements:**

1. **Endpoints:**
    - `/summarize_policy`
        - Accept PDF upload or URL
        - Extract text from PDF/URL
        - Call LLM to generate structured summary in JSON:
            
            ```json
            {
              "Data Collection": {"summary": "...", "risk": "green/yellow/red"},
              "User Rights": {"summary": "...", "risk": "green/yellow/red"},
              "Opt-Out Options": {...},
              "Arbitration Clause": {...}
            }
            
            ```
            
    - `/compare_policies` (optional)

    - Call LLM API to generate summaries
    - Handle long documents using chunking if needed
    - Return JSON output ready for frontend rendering
3. **Database:**
    - Optional: store processed summaries with unique links
4. **Deployment:**
    - Ready for deployment on **AWS/Azure/Render**

Make the code **production-ready, modular, and clean**, with clear functions, endpoints, and error handling. Include comments explaining the logic and usage.
